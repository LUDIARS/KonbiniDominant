# Grid town and compact vector UI

2026-09-10のユーザー指示を正本とする。Phase 1の既存ビルへの建て替え方式と、HUDのbitmap文字方式を更新する。

## Grid town

- キャンペーンとPhase 1専用モードは16×16セル、1セル12m四方の土の地面から開始する。
- 全256セルが出店候補。地面に線と交互の土色を描き、空き地もセル全体でクリック判定する。
- Phase 1に既存の高層ビル・駅ビルは置かない。街の生成revisionはkonbini-grid-town-v1としてFigmentum由来の旧都市と区別する。
- Phase 1は空きセルを1回クリック／タップすると通常の出店コマンドを発行する。ドラッグはカメラ移動のまま。
- 資金不足、既存店舗の占有、選択したチェーン以外の出店は禁止する。出店費用と店舗単位の経済・包囲ルールは維持する。
- 範囲外のクリックは出店しない。セル境界は半開区間で一意に選択する。
- Phase 2以降は同じセルの上階に積む。地面の変更を理由にPhase 2–4の進行は削除しない。

## Square stores

- 1店舗の占有は正方形1セル。単体の建物本体と屋根も正方形。
- 同じチェーン・次元・階の4方向の辺隣接を接続する。斜めだけの接触、反転店舗、アイオーン、別チェーンは通常店舗の連結へ入れない。
- 接続する辺では外側の余白を除き、屋根・壁を隣のセルまで連続させる。L字・穴・分離した島を大きな矩形で塗り潰さない。
- 外に露出する正面の横一列ごとに1枚の連続した看板を描く。列が長いほど看板の幅と文字高が増える。
- 店舗が破壊・置換されたら、次のsnapshotで接続と看板の範囲を再計算する。
- 連結は見た目。店舗ID、費用、人口、スキル、信仰、包囲判定は各店舗のまま。

## Vector font

- Google Fonts公式の[Roboto Mono](https://github.com/google/fonts/tree/main/ofl/robotomono)を使用する。
- 元TTF・OFL・取得revision・SHA-256はdata/fonts/RobotoMonoに保存する。
- tools/bake_vector_font.pyがウェイト500のTrueType輪郭を平坦化し、nonzero windingの台形分割から三角形を作る。OやBなどの穴を保持する。
- 現行の英語UIで使うASCII 32–126をsrc/render/generated/roboto_mono_mesh.incへ焼き込み、Pictorの頂点・index bufferで描画する。フォント画像・テクスチャアトラスは使わない。
- HUDと新しい店舗看板が同じ輪郭データを使う。日本語翻訳や未収録文字の拡張は別途フォント選択とbake対象の更新を要する。
- bakeにはPythonとfontToolsが必要。通常のC++ビルド・ゲーム実行にPythonやフォントのダウンロードは不要。
- 配布ZIPにRobotoMono-OFL.txtを同梱する。

## Compact UI

- Windowsの既定client areaは1280×720、横画面。
- HUDの文字高は通常14px相当。見出しも従来より縮小する。
- 通常操作ボタンは高さ40px、720pではOSの表示倍率にかかわらず8個を1列に並べる。小さい画面では列数を減らす。
- チェーン／スキルの選択カードは標準64px高。表示とヒット判定で同じrectを使う。
- 縮小後もボタン外へのドラッグによる取消、カメラ移動、拡縮、Phase 2以降の長押し建設を維持する。
